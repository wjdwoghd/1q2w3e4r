# Phase 5 위험 우선순위 모델

이 모델은 CVSS(취약점 자체의 기술적 심각도)를 금융서비스의 **조치 우선순위**로 변환한다. 점수는 확률, CVSS 재계산, 공식 규정 준수 판정이 아니다. AI를 호출하지 않으며 같은 입력과 규칙 버전은 같은 결과를 낸다.

## 입력과 출력

`calculate_risk_priorities(match_result, asset_context)`는 Phase 4의 `MatchResult`와 Phase 1의 검증된 `AssetContext`를 받는다. `MATCHED` 상태에 CVE가 여러 개면 CVE별 `RiskResult`를 입력 순서대로 반환한다. 각 결과는 CVE ID, 원본 CVSS 점수, 총점, P1~P4, 적용 규칙(`factor`, `reason`, `points`), 미평가 요소, 규칙 버전 `1.0`을 가진다. `reasons`는 적용 규칙을 점수별 문자열로 표현한다. 총점은 `applied_rules.points`의 합이다.

## 규칙 버전 1.0

수치와 경계값은 `core/risk/rules.py`에서만 관리한다. 이 가중치는 프로젝트의 초기 **조치 순서 정책**이며 경험적 사고 확률이나 법적 기준을 뜻하지 않는다. CVSS 구간은 중복 가산하지 않고 하나만 적용한다.

| 요소 | 조건 | 점수 | 선택 근거 |
| --- | --- | ---: | --- |
| CVSS | 9.0 이상 / 7.0 이상 / 4.0 이상 / 4.0 미만 | 30 / 20 / 10 / 0 | 기술적 심각도를 단계적으로 반영하되, 단독으로 최고 조치 등급에 이르지 않게 한다. |
| CISA KEV | 검증된 카탈로그에 CVE가 등록 | 30 | 실제 악용이 확인된 항목을 기술적 심각도와 동급의 강한 신호로 본다. |
| 인터넷 노출 | `internet_exposed=True` | 15 | 외부 접근 가능한 자산을 먼저 대응한다. |
| 운영 환경 | `production` | 10 | 운영 서비스 중단 및 실제 고객 영향 가능성을 반영한다. |
| 업무 중요도 | `critical` / `high` | 10 / 5 | 핵심 서비스와 높은 중요도 서비스의 영향을 구분한다. `medium`·`low`는 가산하지 않는다. |
| 패치 상태 | `overdue` | 5 | 이미 기한을 넘긴 조치를 소폭 앞당긴다. 일수 정보가 없으므로 지연 기간을 추정하지 않는다. |
| 신용정보 처리 | `credit_information=True` | 5 | 민감한 금융정보 처리 자산에 소폭 가중한다. |

최대 105점이다. 점수는 백분율이 아니다. 고객정보 여부는 신용정보와의 중복 가산을 피하려고 현재 규칙에 포함하지 않았다. EOL은 Phase 4 필수 범위에서 조회하지 않으므로 점수를 부여하지 않고 모든 결과에 `eol`을 미평가로 표시한다.

| 조치 우선순위 | 총점 |
| --- | ---: |
| P1 | 80 이상 |
| P2 | 50~79 |
| P3 | 20~49 |
| P4 | 0~19 |

P1은 심각한 기술적 취약점과 실제 악용 또는 여러 높은 영향 맥락이 겹치는 경우를 우선한다. P2는 한두 개의 강한 신호, P3는 중간 수준의 신호, P4는 현재 검증된 입력에서 낮은 점수인 경우이다. 경계는 초기 정책값이므로 운영 데이터와 전문가 검토 후 규칙 버전을 올려 조정해야 한다. P4도 취약점이 없거나 안전하다는 뜻은 아니다.

예: CVSS 9.8 `+30`, KEV 등록 `+30`, 인터넷 노출 `+15`, 운영 `+10`, 핵심 서비스 `+10`이면 총 95점, P1이다. CVSS 9.8은 원본 기술 심각도이고 95점/P1은 자산 맥락을 포함한 조치 우선순위다.

## 누락 및 실패 처리

- `ERROR`, `AMBIGUOUS`, `UNMATCHED`, `NO_MATCH`는 점수 산정 대상이 아니다. `MATCHED`라도 CVE 목록이 비었거나 중복되면 거부한다.
- CVSS가 없거나 범위 밖·비유한 값이면 `RiskInputError`를 발생시킨다. 0점으로 대체하지 않는다.
- KEV의 `False`는 검증된 카탈로그 스냅샷에 해당 CVE가 없다는 뜻이다. 스냅샷 누락 또는 flag·entry·스냅샷의 불일치는 `RiskInputError`로 거부한다. KEV 조회 실패는 Phase 4에서 `ERROR`가 된다.
- 자산 맥락이 없거나 잘못되면 거부한다. 패치 상태 `unknown`은 패치 가산 없이 `unassessed_factors`에 `patch_status`를 기록한다. 이는 `current`와 동의어가 아니다.
- EOL은 검증된 입력이 없으므로 항상 `unassessed_factors`에 기록한다. EOL이 `False`라고 추정하지 않는다.

Phase 5 계산은 순수 함수로 유지한다. Phase 6은 저장된 MatchResult와 자산 Context로
이 함수를 호출하고 RiskResult를 Finding 관측에 보존한다. 화면 표시는 후속 단계다.
